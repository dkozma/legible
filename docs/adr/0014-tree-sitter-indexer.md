# The indexer: tree-sitter grammars from npm, AST proofs, Lezer as the Text-tier fallback

M2 moves parsing into the indexer utility process (`packages/indexer`, run by `apps/desktop/src/main/indexer.ts`). It builds Change Sets (the diff engine moved with it), highlights with tree-sitter, extracts Symbols and Connections, and proves Structural Fragments from the syntax tree.

**Grammars come from their npm packages, pinned.** The official grammar packages now ship a prebuilt WASM and their queries. `packages/indexer/package.json` pins each one, all loading in web-tree-sitter 0.27 (ABI 14–15). `grammars/manifest.json` names each language's WASM, highlights and tags files, and `grammars/queries/` holds Legible's own tags queries: imports aren't in upstream tags, and neither are type uses, constants or C calls. The desktop build copies only the needed files into `out/main/grammars` (about 31 MB). A test loads every grammar and compiles every query, so an ABI or query mismatch fails CI, not the app. Bundled: 16 Full-tier languages (TypeScript, TSX, JavaScript, JSX, Python, Go, Rust, Java, C, C++, C#, Ruby, PHP, Scala, Lua, Elixir, OCaml) and 8 Structural-tier ones (JSON, shell, CSS, HTML, YAML, TOML, HCL, Zig). Kotlin's published highlights don't match its grammar, and Dart's WASM doesn't load, so both stay Text tier for now.

**Highlight precedence is by specificity.** Upstream queries disagree on order: JavaScript and Python list `(identifier) @variable` first and refine it later, while Go lists specific patterns first. When two patterns capture the same node, the one with more nodes, fields and predicates wins, and order breaks ties. The inner node wins over the outer one, as before.

**Lezer stays, for Text-tier languages only.** Removing it would drop highlighting for Kotlin, Swift, SQL, Markdown, SCSS and a dozen others. Languages without a bundled tree-sitter grammar keep the M1 highlighter (ADR 0009). Its token-based whitespace proofs are gone.

**AST proofs.** A chunk is Structural when applying it alone to Base gives the same syntax tree as Base: the same node types in the same shape and the same leaf text, with only whitespace between tokens differing. Strings, templates and regexes are leaf text, so whitespace inside them still counts, and comment text is compared line by line with each line trimmed. The check runs only where the grammar sees everything whitespace can change (ASI, Python's indentation and C's preprocessor all show up in the tree): TS/JS, Java, C, C++, C#, Rust, Go, JSON and Python, never inside JSX. It doesn't run in HTML, CSS, YAML, shell, Markdown or PHP, where whitespace between tokens is content or a combinator. Proof tags stay `whitespace` and `formatting`. The plan's `rename-local`, `move` and `extract` are not attempted: moves can change behavior (see the domain types), and local renames need scope queries few grammars ship.

**Resolution.** The plan's deterministic rules come first: same file, imports (relative and workspace-package JS/TS, Python packages, Go import paths, Rust `use`, Java packages, C includes), the receiver's class or module, and the same Go or Java package. Then the only definition by that name in the indexed code counts as "likely". Several definitions make an Ambiguous Connection that lists every candidate, and none means external. Plain identifier uses resolve only by the deterministic rules, never by name, and a name being declared (a local, parameter or destructured binding) isn't a use. In JS/TS, Python, Go, Rust and PHP a bare name never resolves to a class member, since members need `this.` or `self.`. A built-in method name (`get`, `push`, `then`…) on a receiver of unknown type is external, not "likely": `this.items.get()` is far more often `Map#get` than the one `get` the index holds. Neighbors are 1 hop: imported files, the package's own files, and files that `git grep -w` finds for changed Symbols' names and unresolved ones. A name found in more than 40 files is too common to search, and its Connections stay ambiguous. The search runs `git grep -l` for all names at once, then checks which names each file holds. `git grep -o` with hundreds of patterns took 9 s on this repository, against under a second for the whole index this way. `tsconfig` path aliases aren't resolved yet.

**Resolution rules, revised** (issue #74, measured with the SCIP eval in `evals/`). Four kinds of false positive led to four changes:
- **Locals.** Per-language `locals.scm` queries (TypeScript/JavaScript, Python, Go) capture function and block scopes and the names bound in them. A plain use of a parameter or local is never a Connection. A member use on one (`order.save()`) resolves only through the local's declared type (`order: Order`, `new Order()`, `&Order{}`). A library or built-in type makes it external.
- **Evidence for "likely".** The only definition by a name is "likely" when something else points at it: the file imports its file (within 2 hops), they share a Go or Java package, or the receiver's declared type is its class. Otherwise it's a new status, "possible". Possible Connections stay out of Fragment graph edges, reach and Explanations, and are shown greyed out. Among several candidates, the only one with evidence is "likely". The rest stay ambiguous.
- **Module resolution.** Go imports are local only under a `go.mod` module path, resolved exactly below it. Python absolute imports try the importing file's source root first. Java tries the importing module's source root (`src/main/java`…), and C/C++ tries `compile_commands.json` include directories. Only then does suffix matching apply, and several matches make the import ambiguous.
- **Downstream.** An Ambiguous Connection counts 1/n per candidate toward callers and blast radius. Only resolved Connections are hard ordering constraints in the Walkthrough; likely ones are hints for the planner.

## Consequences

- The parse cache stores results, not trees: tokens, Symbols, references and imports per blob OID and grammar version (see below), in memory and in `<userData>/index-cache` (v8-serialized, LRU, 256 MB).
- In blobless Pull Request clones, the neighbor search covers only the changed files' directories, and gives up past 500 blobs to download. The Connections panel says when Used by is incomplete.
- Grammar upgrades are dependency bumps, checked by the grammar test. The parse cache key carries the grammar package's version and a hash of the language's query text, including queries from nested packages (TypeScript's JavaScript, C++'s C) and Legible's own. Upgrading a nested package or editing a query invalidates old entries on its own.
