Concurrent partial refunds can reuse an idempotency key

The key is built from balance.count, read before the gateway call. Two support agents refunding the same order at once read the same count, send the same key, and the gateway treats the second refund as a retry of the first. The customer gets one refund; the order records two.

Confirmed by Verification · OpenAI cross-checkNo lock or transaction wraps the read and the gateway call. Reproduced with two interleaved calls in the trace.
Suggested fix
+ const seq = await this.orders.nextRefundSeq(orderId);
